# 路线图

目标：可上线的 4v4 网页团队竞技。每个里程碑都以「可运行、可验证」为准，不追求一次做完。

- [x] 规则记录：`docs/pubg-mobile-tdm-rules.md`
- [x] 技术选型与架构：`docs/architecture.md`
- [x] 协议定义：`docs/protocol.md`

## M1 多人移动切片（完成，待双人手测）

- [x] Go 权威房间：加入/离开、队伍分配、出生点、20Hz 快照
- [x] 服务端移动模拟与 AABB 碰撞
- [x] 客户端预测 + 重放 + 回拉，远端玩家插值
- [x] 仓库图 blockout（中央通道、箱体掩体、边界）
- [x] 指针锁定、WASD/疾跑/跳跃、第一人称视模型
- [x] 无头浏览器：加载、连接、进入对局的冒烟验证
- [ ] 真实双人联机验收（浏览器手测）

验收：两名玩家在浏览器中互相看见移动，位置一致，无明显抖动；单人移动手感顺滑。

## M2 射击与生命值（基础版完成）

- [x] 服务端命中判定（hitscan + 射线/圆柱、箱子遮挡）
- [x] 射速限制、身体/头部伤害、血量、死亡与 3 秒复活、出生保护
- [x] 曳光、命中标记、击杀播报、死亡倒计时 UI
- [x] 基础延迟补偿：按射手上报的 RTT 回溯目标历史位置
- [x] 护甲/头盔减伤（M5 完成）
- [x] 屏幕受击反馈（红边）
- [x] 多武器与弹匣/换弹（M5 完成）
- [ ] 80ms RTT 下的手感调优与验收

验收：两人可以互相击杀并复活；服务端集成测试已覆盖击杀、计分与复活。

## M3 比赛流程（基础版完成）

- [x] 等待 → 倒计时 → 进行 → 结算状态机；双方都有玩家时自动开局
- [x] 40 杀 / 10 分钟胜负判定，比分实时同步
- [x] 开局重置出生点、血量、K/D；结算 8 秒后自动开始下一局
- [x] 客户端比分、计时、结算面板、按住 Tab 的计分板
- [x] 比赛参数可配置（`-match-seconds` / `-score-limit`）
- [ ] 挂机判定与掉线补位（依赖 M4 机器人）
- [ ] 平局/加时规则细化

验收：完整对局可以开始、计分、结束并自动重开；单元测试覆盖状态机与 40 杀上限，
双客户端集成测试覆盖开局与比分。

## M4 机器人（基础版完成）

- [x] 服务端机器人：A* 网格导航、索敌、开火
- [x] 人数不足自动补位；真人加入时机器人让位
- [x] 难度参数：反应时间、瞄准误差、转向速度、点射节奏（每个机器人随机）
- [ ] 掩体利用、撤退/包抄、投掷物
- [ ] 难度档位与外部配置

验收：1 名真人 + 7 个机器人可完整开局并计分；集成测试覆盖补位、让位与移动。
