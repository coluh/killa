# 架构说明

> 状态：M7（部署产物就绪）。后续里程碑会持续更新本文档。

## 总体结构

```
浏览器 (TS + Three.js)
   │  HTTP  静态页面
   │  WSS   控制/状态消息（MVP：JSON）
   ▼
Go 进程
   ├─ HTTP 服务：静态资源、/healthz、/ws 升级
   ├─ 传输层：连接、消息编解码、限流
   └─ 房间循环：20Hz 权威模拟、快照广播、比赛状态机（后续）
```

单进程多房间：`Manager` 维护房间池（默认上限 16），优先把玩家放进人最多的未满房间，
满 8 人后创建新房；空房保留复用。同时在线 < 100 的量级下单进程够用；更大规模再拆
进程/匹配服，房间循环本身不依赖全局状态。

## 网络模型

- **服务端权威**：位置、朝向、血量、命中、比分全部由服务端计算，客户端只上报输入。
- **输入 60Hz**：客户端每帧发送 `input`（dt、移动轴、疾跑、跳跃、朝向）。
- **快照 20Hz**：服务端按 tick 广播所有玩家状态，并为每个玩家附带其已处理的输入序号 `ack`。
- **断线重连**：客户端指数退避重连（最多 5 次），重连后重新 `join` 并重建场景；
  灵敏度、音量与配装保存在本地。断线期间对局仍继续，重连会以新玩家进入当前房间。
- **客户端预测**：本地用与服务端一致的 `step()` 立即移动；收到快照后按 `ack` 丢弃已确认输入并重放未确认输入。
- **误差修正**：预测位置与服务端位置偏差超过 `0.75m` 时回拉到服务端状态，否则保持本地预测，避免抖动。
- **远端插值**：其他玩家用指数平滑逼近最新快照位置，掩盖 20Hz 的跳变。
- **命中判定**：服务端 hitscan，射线与圆柱体求交、箱子 AABB 遮挡；按射手 RTT/2
  回溯目标历史位置（最多 125ms）。客户端只收到 `shot` 事件用于曳光与命中提示。
- **比赛状态机**：`waiting → countdown → live → ended`，在房间 tick 内推进；
  击杀只在 `live` 期间计入队伍比分，40 杀或 10 分钟结束，8 秒后自动重开。
- **武器与配装**：服务端武器表驱动伤害/射速/弹匣/换弹/扩散；配装只改
  `Loadout`，在下一次复活时装备，避免中途换枪刷新弹匣。护甲按伤害的 35%
  吸收并消耗耐久，复活重置。
- **垂直碰撞**：箱子可站上去；水平碰撞按脚底高度过滤，支撑面取脚下最高箱顶。
  服务端与客户端使用同一算法，快速下落时用“下落前高度”判定落点避免穿模。
- **表现**：Three.js 几何/描边风格、程序化 WebAudio 音效、出生点光环与倒计时 HUD。
- **机器人**：与真人共用同一套玩家状态与命中管线，在房间 tick 内运行。用 1m
  网格 A* 绕开箱子，视线检测后停下瞄准射击；人数不足时自动补位，真人加入时
  让位。行为参数（反应、瞄准误差、转向速度）按机器人随机。

M1 的已知简化：

- 碰撞体按「无限高」处理，不能跳上箱子顶部。
- `dt` 由客户端上报，服务端仅做上限截断（0.1s）；不做完整的时间戳校验。
- JSON 文本协议，单条消息 < 4KB；后续换二进制并评估 WebTransport。

## 反作弊基线

- 服务端从不信任客户端位置/朝向以外的结果；移动由服务端重新模拟。
- 所有浮点输入做 NaN/Inf 检查、范围截断；名字截断并过滤控制字符。
- WebSocket Origin 白名单；全局连接数上限 256、单连接 400 消息/秒限流、
  消息大小与房间人数受限。
- 射击上线后：命中判定、射速、弹药、后坐力全部服务端计算，客户端只上报「开火意图」。
- 上线前补充：速率限制、连接鉴权（游客 token）、日志与异常检测。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `server/internal/protocol` | 双端共享的消息结构（JSON） |
| `server/internal/game` | 世界/碰撞、移动模拟、房间循环、玩家状态 |
| `server/internal/transport` | WebSocket 连接生命周期、读写泵、Origin 校验 |
| `server/cmd/killa` | 配置、路由、静态资源、优雅退出 |
| `client/src` | 渲染、输入、网络、预测/插值、HUD |

## 部署

- 多阶段 Docker：Node 构建前端 → Go 编译 → Alpine 运行镜像（非 root，仅二进制 + dist）。
- `docker-compose.yml` 启动 app 与 Caddy；Caddy 自动申请证书并反代 `wss://`，
  同时负责压缩、静态缓存与安全响应头。
- 国内 VPS 需完成 ICP 备案后才能使用 80/443；部署与排障见 `docs/deploy.md`。
- 观测：`/healthz`、加入/离开/开局/结算日志、Docker healthcheck 与日志轮转。
- 压测：`server/cmd/loadtest`（8 客户端，快照频率与 RTT）。
